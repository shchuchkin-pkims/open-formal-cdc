# Файл конфигурации (YAML)

Версия этапа 2. Переходы находит структурный анализ (`options.structural: true`, по умолчанию), он же предлагает проверки. Переходы и проверки из файла дополняют и переопределяют найденные.

## Пример

```yaml
design:
  top: handshake_mux            # верхний модуль
  files: [handshake_mux.sv]     # пути относительно файла конфигурации
  params: {BAD: 0}              # параметры верха (ключ -G yosys-slang)
  slang_args: []                # прочие ключи read_slang, например --relax-enum-conversions

clocks:                         # такты: имя домена и порт верха
  - {name: a, port: clk_a}
  - {name: b, port: clk_b}

resets:                         # сбросы: порт, полярность, домен, режим
  - {port: rst_a_n, active: low, clock: a}             # mode: init (по умолчанию)
  - {port: rst_b_n, active: low, clock: b, mode: free} # может прийти в любой момент

inputs:                         # входы верха с доменом; остальные входы асинхронные
  - {port: go, clock: a}

checks:
  - name: data_stable           # имя проверки
    template: en_stable         # шаблон свойства
    data: u_tx.data             # параметры шаблона: сети плоского нетлиста
    enable: u_rx.cap
    clock: b
    expect: proven              # ожидаемый итог (для примеров и регрессии)

options:
  time_models: [ticks, clk2ff]  # модели времени; по умолчанию [ticks]
  reset_steps: 4                # шагов начального сброса
  cover_depth: 40               # глубина поиска; FAIL или TIMEOUT до неё не означает вакуумность
  timeout: 300                  # лимит на задачу SBY, с
  prove_engine: abc pdr
  cover_engine: smtbmc          # можно выбрать решатель: smtbmc boolector, bitwuzla, z3, cvc5
  m5_prove_engine: aiger rIC3   # необязательно: движок только для заданий с M5
  m5_cover_engine: smtbmc boolector  # необязательно: cover-движок только для M5
  m5_cover_depth: 80            # необязательно: глубина покрытия только для M5

variants:                       # варианты того же проекта (верный и испорченные)
  data_changes:
    params: {BAD: 1}
    expect: {data_stable: cex}
```

Вместо `files` можно задать `design.filelist`: текстовый список исходников с путями относительно самого списка. Поддерживаются `exclude` по маске имени файла, `extra_files`, а также директивы `+incdir+<каталог>` и `+define+<имя>[=<значение>]`; они преобразуются в аргументы yosys-slang с абсолютными путями.

## Такты из SDC и группы тактов

```yaml
design:
  top: top
  files: [top.sv]
  sdc: top.sdc                  # такты, группы и домены входов и выходов из SDC
clock_groups: [[a, a_div2], [b]] # такты одной группы связаны (один домен), группы асинхронны
```

Поддерживаемое подмножество SDC: `create_clock`, `create_generated_clock`, `set_clock_groups -asynchronous`, `set_input_delay -clock`, `set_output_delay -clock`. Tcl не исполняется, команды только разбираются.

- Если в SDC нет `set_clock_groups`, такты считаются связанными, как в анализе времени, и переходов между ними нет.
- Без SDC и без `clock_groups` каждый такт из `clocks` – отдельный асинхронный домен.
- Такт, полученный делением в триггере, связан со своим исходным тактом.
- Выход, привязанный к такту (`set_output_delay`), тоже считается приёмником перехода.

## Структурный анализ

Анализ идёт по плоскому нетлисту Yosys. Для каждого перехода он определяет:

| Схема | Признак | Предлагаемая проверка |
|---|---|---|
| `ndff` | один бит, источник подключён напрямую, цепочка из 2 и более триггеров приёмника с единственной нагрузкой | нет (`structural`) |
| `ndff_bus` | то же для шины | `gray` на регистре источника |
| `mux_enable` | приёмник загружает данные по разрешению (мультиплексор с рециркуляцией или вход EN) | `en_stable` с найденным разрешением |
| `static` | источник помечен `cdc_static` | допущение `static`, проверяется двойником |
| `user_cell` | источник или приёмник помечен `cdc_sync` (`synchronizer`, `async_reg`) | нет |
| `gray_bus` | шина помечена `cdc_gray` (`gray_code`) | `gray` |
| `handshake` | приёмник помечен `cdc_handshake` | `en_stable`, если найдено разрешение |
| `none` | ничего из перечисленного | нет (`no_scheme`) |

Мультиплексор сброса (одна ветвь – константа) не считается логикой и не рвёт цепочку синхронизатора. В отчёте также есть:
- логика перед первым каскадом (`logic: combo`) и между каскадами (`between_stages`);
- ветвление – один бит источника идёт на несколько синхронизаторов;
- сходимость – выходы нескольких синхронизаторов сходятся в одной логике;
- входы без домена (они не считаются источниками);
- пары «источник–приёмник» с разными сбросами в одном тактовом домене (`reset_crossings`, схема `reset_domain`), включая сброс с выхода триггера; в проверки они попадают только при `options.rdc_checks: true`;
- сбросы, сформированные триггером одного домена и поданные на reset-пин триггера другого (`reset_signals`), с группировкой потребителей и полярностью;
- комбинационная логика на reset-пинах (`reset_logic`): `$and` получает структурный `unsafe`, declaration и producer mismatch также выводятся отдельно; AND/OR с двумя и более независимыми входами образуют RDC-005, `$mux` без локального синхронизатора образует RDC-006;
- голова reset-цепочки с D, привязанным к asserted-значению (`reset_stuck`), получает структурный `unsafe`;
- authored reset-цепочки (`reset_chains`) и домены без синхронизатора при наличии цепочки в других (`reset_domain_misses`);
- dual-use сети с async и sync reset-потребителями (`reset_dual_uses`).
- простые `$mux`, выход которых идёт на вход CLK триггера (`clock_muxes`). При `options.clock_mux_checks: true` предлагается проверка фаз; атрибут `cdc_static` на select становится допущением `static`.

Имена найденных переходов – `источник->приёмник` (например, `u_tx.ptr->u_sync.s1`), имена проверок – `gray_<источник>` и `en_<источник>__<приёмник>`. По этим именам задаются ожидания в `variants`; раздел `variants.base` дополняет базовый вариант.

## Ячейки синхронизации

Встроенная библиотека (`structural/cells.py`): Xilinx XPM (`xpm_cdc_single`, `xpm_cdc_array_single`, `xpm_cdc_gray`, `xpm_cdc_handshake`, `xpm_cdc_pulse`, `xpm_cdc_async_rst`, `xpm_cdc_sync_rst`), Intel `altera_std_synchronizer`, OpenTitan `prim_flop_2sync`. Свои ячейки описываются так:

```yaml
cells:
  - module: sync2             # имя модуля
    clocks: {dst: clk}        # роль -> тактовый порт (src, dst)
    inputs: {d: null}         # порт -> роль; null - асинхронный вход, его синхронизирует ячейка
    outputs: {q: dst}         # порт -> роль
    through: [d]              # входы, данные которых переходят в домен dst
    scheme: ndff              # схема внутри (для отчёта)
```

Для структурного анализа ячейка читается как «чёрный ящик» (`--blackboxed-module`). Её выходы относятся к домену своего такта, переход через неё получает схему `user_cell`, а вход, поданный из чужого домена, – переход без схемы. Формальные задачи читают проект целиком, вместе с содержимым ячейки.

**T-CELL.** Каждая ячейка из `cells` (кроме помеченных `prove: false`) один раз проверяется отдельным прогоном: верхний модуль – сама ячейка, такты – её роли, домены входов – из `inputs`, входы без роли асинхронны. Дополнительно можно задать `params` и `resets` ячейки. Если внутри нет переходов `unsafe`, `no_scheme` или `unresolved`, ячейка доказана, и все переходы через её экземпляры получают `safe` с причиной «cell … proven»; иначе – `unsafe` или `unresolved` с причинами из прогона ячейки. Итоги прогона ячейки – в `build/<имя>/cells/<модуль>/`. При `options.m5_checks: true` M5-предложения строятся и внутри ячейки с теми же ограничениями, что на верхнем уровне; лимиты и движки наследуются от основной конфигурации. Полные внутренние исходы и покрытия дополнительно сохраняются в секции `cells.<модуль>` файла `results.json`, поэтому сводный `safe` можно проследить до конкретной проверки.

Ограничение: пары «запрос – подтверждение» (T-HS) пока ищутся только среди переходов `ndff`, поэтому для рукопожатия на объявленных ячейках проверка протокола не предлагается.

## Частоты тактов и импульсы

```yaml
clocks:
  - {name: a, port: clk_a, period: 4}     # нс; можно взять из SDC
  - {name: b, port: clk_b, period: 10}
options:
  clock_ratio: periods        # free (по умолчанию) | periods
  pulse_checks: true          # предлагать T-PULSE для однобитных синхронизаторов
  pulse_min_edges: 2          # сколько фронтов приёмника должно видеть каждое значение
variants:
  free_clocks:
    options: {clock_ratio: free}   # вариант может переопределять options
  read_reset:
    resets: {rrst_n: {mode: free}} # и режим сброса (init | free)
```

`clock_ratio: periods` ограничивает каждую пару тактов (Kapschitz и Ginosar): между двумя соседними фронтами медленного такта укладывается от ⌊r⌋ до ⌈r⌉ фронтов быстрого, где r – отношение периодов; для целого r – ровно r. Фаза свободна. Модель – надмножество реальных тактов, поэтому «доказано» в ней верно и для реальной схемы.

Шаблон `pulse` (T-PULSE): каждое значение источника видят не меньше `min_edges` фронтов такта приёмника, иначе синхронизатор может пропустить импульс. Значение, которое держится с момента сброса, не проверяется.

## Допущения о среде (T-ENV)

```yaml
assumptions:
  - name: no_write            # допущение о среде: касается только входа верха
    kind: constant            # constant | static | hamming1 | onehot0
    signal: wr                # или signals: [a, b] - склеиваются в шину
    value: 0                  # для constant
  - name: cfg_static          # допущение о внутренней сети: проверяется двойником
    kind: static
    signal: cfg
    applies_to: [c1, c2]      # к каким проверкам применять; по умолчанию ко всем
    expect: proven            # ожидаемый итог двойника
```

| Вид | Смысл (после начального сброса) |
|---|---|
| `constant` | сигнал всегда равен `value` |
| `static` | сигнал не меняется |
| `onehot0` | установлено не больше одного бита |
| `hamming1` | за фронт такта `clock` меняется не больше одного бита (код Грея) |
| `quasi_static` | сигнал меняется только в шаге, где `allow` равен `allow_value` (в этом или предыдущем шаге); например, настройка меняется, только пока блок выключен |
| `clock_select` | пока `on` не соответствует `select` (`on0`/`on1`), `select_d` обязан оставаться равным `select`; до активации `select_d = init` (по умолчанию 0). Используется для glitch-free clock mux с `verify: false` |

Дополнительно:
- `signals_match` (шаблон имени, glob) и `exclude` – вместо перечисления сетей, когда их десятки;
- `verify: false` – допущение принимается как обещание о среде (например, о программе) и не проверяется двойником; его состояние `environment`, а переходы, которые на него опираются, получают `safe_assuming`.

Каждое допущение подключается как `assume` ко всем проверкам (или к перечисленным в `applies_to`).

- Если допущение касается только входов верха, это **допущение о среде** (`environment`): проверить его на проекте нельзя.
- Если оно касается внутренней сети, утилита строит **двойника** – отдельную задачу, где то же условие стоит как `assert`. Двойник идёт только с допущениями о среде, без других внутренних допущений: так нет круговых рассуждений.

Состояния допущения: `environment`, `proven`, `refuted` (у двойника контрпример), `unverified` (двойник не дал ответа).

## Переходы и вердикты

```yaml
crossings:
  - name: data
    from: {signal: u_tx.data, clock: a}
    to: {signal: u_rx.data_out, clock: b}
    scheme: handshake         # none, ndff, ndff_bus, gray_bus, mux_enable, handshake, pulse_toggle,
                              # async_fifo, reset_sync, reset_domain, clock_mux, static, user_cell, external_sync
    checks: [data_stable]     # проверки, которые доказывают этот переход
    assumptions: []           # допущения, на которые переход опирается напрямую
    expect: safe              # ожидаемый вердикт
```

| Вердикт | Когда |
|---|---|
| `safe` | все проверки `proven`, все допущения, на которые опирается переход, доказаны |
| `safe_assuming` | то же, но в цепочке есть допущения о среде |
| `unsafe` | у одной из проверок контрпример |
| `no_scheme` | схема `none` |
| `structural` | схема принимается по структуре (`ndff`, `reset_sync`, `user_cell`) и проверок к ней нет |
| `note` | запись authored reset-цепочки, не нарушение |
| `warning` | сырой reset-источник рядом с reset-цепочкой, требуется ревью |
| `unresolved` | всё остальное; в отчёте причины: проверка не решена, допущение опровергнуто или не проверено, нет проверок |

Цепочка допущений учитывается целиком: если проверка опирается на внутреннее допущение, а его двойник – на допущение о среде, вердикт будет `safe_assuming`. Опровергнутое допущение отзывает все переходы, которые на него опираются.

Утилита пишет `cdc_model.json`: такты, сбросы, входы, допущения с состояниями, переходы с вердиктами и проверки с итогами по каждому варианту.

## Среда
- **Такты** свободны: соотношение частот не ограничено (режимы `ratio`, `fixed` – этап 3).
- **Начальный сброс** держится `reset_steps` шагов. В модели тиков в это время срабатывают все домены, в `clk2fflogic` такты идут вместе, поэтому срабатывает и синхронный сброс.
- **Сброс `mode: free`** может снова прийти в любой момент после начального (проверки RDC).
- **Вход с доменом** меняется только по фронту своего такта. Вход без домена асинхронный, он может меняться на любом шаге.

## Сети
Имена – как в плоском нетлисте Yosys после `flatten`: `u_tx.data` – сеть `data` в экземпляре `u_tx`. Порт верха можно указать просто по имени. Если сети нет, утилита сообщает об ошибке и предлагает похожие имена.

## Шаблоны

| Шаблон | Параметры | Свойство |
|---|---|---|
| `gray` | `signal`, `clock` (такт источника) | за фронт такта источника меняется не больше одного бита |
| `en_stable` | `data`, `enable` (1 бит, домен приёмника), `clock` (такт приёмника), `enable_active: high/low` | пока разрешение захвата активно, данные не меняются с последнего фронта приёмника |
| `pulse` | `signal`, `clock` (такт приёмника), `src_clock`, `min_edges` | каждое значение источника видят не меньше `min_edges` фронтов приёмника |
| `onechange` | `signals` (список сетей), `clocks` (домены вне сброса) | из перечисленных бит источника за шаг меняется не больше одного. Предлагается анализом как T-GLITCH (`glitch_<первый каскад>`: все источники логики перед синхронизатором) и T-CONV (`conv_<точка сходимости>`: источники синхронизаторов, выходы которых сходятся в одной логике или в одном регистре) |
| `nohazard` | `d` (вход первого каскада), `inputs` (все входы его комбинационного конуса), `clock` (такт приёмника) | M4: каждый вход независимо берёт значение на предыдущем или текущем фронте приёмника; результат на смешанном векторе должен быть значением, которое `d` уже имело в текущем периоде приёмника. Отдельные покрытия подтверждают изменение и skew-инъекцию. При `options.hazard_checks: true` предлагается вместе с `onechange`, если все входы конуса – триггеры одного известного домена; конусы с памятью пока пропускаются. `options.hazard_domain_inputs: true` дополнительно включает все триггеры исходного домена и выходы чтения памяти того же домена записи как overapproximation для неполных границ конуса (больше работы для решателя, по умолчанию выключено). Старое/новое значение ставится на `DATA` конкретной ячейки чтения, а не на содержимое всей памяти; память с неизвестным доменом записи не поддерживается. `options.hazard_async: true` дополнительно разрешает независимые исходные домены и память из другого домена: skew берётся между предыдущим и текущим фронтами приёмника, а разрешённое значение должно уже встречаться в текущем периоде приёмника. В вердикте перехода M4 заменяет более слабый `onechange`, а сама эвристика остаётся отдельной проверкой для сравнения. После извлечения дополнительные внутренние входы, не найденные структурным анализом, отклоняются защитным условием. Модель не описывает вентильные задержки |
| `hs_req` | `req` (запрос), `ack` (подтверждение, синхронизированное в домен запроса), `clock` (такт запроса) | T-HS: запрос меняется только тогда, когда подтверждение его догнало (`ack == req`); годится для четырёхфазного и переключающего рукопожатия. Анализ находит пару сам: два однобитных синхронизированных перехода навстречу, источник обратного зависит от выхода синхронизатора прямого; инициатор – сторона, чей запрос зависит от внешних входов. Проверка привязывается к переходам запроса, подтверждения и данных |
| `nonew` | `src`, `dst` (сети или списки сетей с одинаковой суммарной шириной), `clocks`, `msi`, `m5` | T-META: приёмник никогда не показывает значение или векторную комбинацию, которую источник не держал; решатель выбирает любое значение. На первые каскады из `msi` ставится модель M2a, на пары из `m5` – M2a и M5. Для шин `ndff_bus` предлагается при `options.meta_checks: true`. При `options.m5_checks: true` для каждой точки сходимости также предлагается `m5_conv_<точка>`: списки `src`/`dst` склеиваются в векторы, а M5-цели каждой цепочки имеют собственный `clock`. Полная ширина каждого источника должна совпадать с шириной приёмника: сжатие нескольких битов в один флаг такой проверкой не искажается. Gray при нескольких изменениях за период приёмника может дать настоящий контрпример; рабочее соотношение частот задаётся через `clock_ratio: periods`. При `options.msi_ablate: true` контроль `*_noms` сравнивает `robust`, `sensitive` или `unresolved`, а `baseline_of` сохраняется в JSON |

## Локализация и CEGAR

Для явно объявленной проверки можно задать разрезы нетлиста:

```yaml
checks:
  - name: stable
    template: en_stable
    data: data_q
    enable: cap
    clock: b
    cut: [dst_data_q]       # точные полные имена сетей, не glob и не битовые срезы
    cut_mode: state         # state (рекомендуется) | value (по умолчанию)
```

`state` заменяет состояние триггеров, управляющих выбранной сетью, свободным значением на их собственных фронтах. `value` освобождает драйвер выбранной сети в любом шаге и является более грубой надмоделью. Тактовые и сбросные порты разрезать запрещено. Доказательство на такой надмодели консервативно, но её контрпример или покрытие может быть ложным.

```bash
open-formal-cdc cegar config.yaml --check stable --rounds 6 -x local
```

Команда по одному убирает разрезы, пока контрпример сохраняется, и затем обязательно запускает полную модель. Нетлист каждого варианта строится один раз; раунды повторно используют его только после проверки точного совпадения `frontend.ys`. Если в VCD контрпримера найдены разрезанные сигналы, сначала проверяются переключившиеся ближе к шагу нарушения; это эвристика порядка, а не доказательство зависимости. Для каждого раунда сохраняется путь к VCD, если она есть. Окончательный `proven` требует доказательства и всех покрытий **без разрезов**; окончательный `cex` тоже подтверждается только на полной модели. Поле `abstract_cex` в `cegar.json` имеет значения `confirmed`, `discharged`, `unresolved` или `none`. `cut_evidence` фиксирует формальный исход по каждому разрезу: `not_required` – контрпример сохранился без него; `discharges` – после удаления разреза доказательство прошло во всех моделях; `inconclusive` – контрпример исчез, но доказательство не завершилось; `untested` – раунд не выполнялся. Поле `proof` раунда содержит статусы доказательства отдельно от покрытий. Эти свидетельства относятся к конкретным раундам и не доказывают глобальную ненужность разреза или минимальность множества. Все раунды, их разрезы и статусы сохраняются; абстрактные покрытия не засчитываются как свидетели полной модели. Выбирается ровно одна явно объявленная проверка. Если `cut` не задан, начальный фокус для `en_stable` строится по границе конуса `enable`: конус `data` и непосредственные опоры свойства сохраняются, остальные триггеры `enable` абстрагируются. Для `gray` измеряемая шина сохраняется, а вспомогательные триггеры в конусе её next-state логики становятся `state`-разрезами. Выбранные сети и правило записываются в `focus.json`. Для остальных шаблонов и при пустой границе `cut` нужно задать вручную.

## Ablation допущений

`open-formal-cdc ablate <config> [-o каталог] [-x executor] [--check имя]` выполняет полный прогон и по одному прогону без каждого допущения. `ablation.json` сохраняет статусы каждой проверки и вердикта. Класс `helps` означает, что без допущения появляется контрпример; `redundant` — что все результаты совпали; `changes` — иное изменение результата. Допущения не добавляются и не удаляются автоматически.

## Итоги
- `proven` – доказательство прошло, все покрытия достигнуты;
- `cex` – контрпример, в отчёте глубина и путь к VCD;
- `vacuous` – зарезервировано для случая, когда недостижимость покрытия доказана отдельной неограниченной проверкой; текущий ограниченный `cover` такого результата не выдаёт;
- `unknown` – лимит времени, недостижение покрытия в пределах `cover_depth` или нет ответа движка;
- `error` – ошибка сборки или движка;
- `model_mismatch` – модели времени дали разные итоги. Это ошибка утилиты, её нужно разобрать.

## Запуск

```
open-formal-cdc run examples/handshake_mux/ofcdc.yaml -x ssh:user@10.8.1.14:~/.ssh/id_ed25519_homepc
```

`-x local` запускает на этой машине, если на ней есть OSS CAD Suite (путь можно задать переменной `OFCDC_TOOLS_BIN`). Итоги пишутся в `build/<имя конфигурации>/results.json` рядом с конфигурацией. Код возврата 1 означает, что итог хотя бы одной проверки не совпал с ожидаемым.
