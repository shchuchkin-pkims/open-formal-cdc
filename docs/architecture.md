## 1. Цель и критерии

**Цель.** Для каждого перехода между тактовыми доменами (и доменами сброса) выдать обоснованный итог: «доказано», «контрпример» с трассой или «не решено» с причиной. Средства только открытые: Yosys, yosys-slang, SymbiYosys, ABC, rIC3.

**Что значит «уровень Jasper».** На референсном блоке, конфигурация 2clk (локальные данные не публикуются):
1. Воспроизводятся все известные классы находок: отсутствие схемы, раздельные сбросы, логика перед синхронизатором и сходимость с моделью метастабильности.
2. Доля «не решено» плюс «не обработано» не больше, чем у Jasper (10 + 85 из 303).
3. Время не больше 20 минут на ПК (16 потоков).
4. Ложных контрпримеров среды меньше, чем у Jasper (136), за счёт файла допущений и вывода допущений.
5. На регрессионных наборах (раздел 9) 100 % ожидаемых ответов.

**Где можно стать лучше Jasper** [FP 5.4]:
- покрытие предпосылки у каждого свойства (у Jasper на референсном блоке покрытий ноль);
- явные допущения среды, каждое со своим проверочным утверждением;
- отдельный итог «контрпример среды»;
- вычисление квалификатора по пути данных, а не выбор первого синхронизатора (Kalel 2024);
- подсказка допущений из контрпримеров (Plassan, гл. 5).

## 2. Основные решения

| № | Решение | Почему |
|---|---|---|
| Р1 | **Единая основа – один нетлист Yosys.** Структурный анализ, свойства и задания SBY работают с одним и тем же разобранным проектом (`design.il` и `netlist.json`) | Нет проблемы сопоставления имён между анализатором и SBY [ST 5.2] |
| Р2 | **Своя тонкая структурная часть** на этом нетлисте; внешние анализаторы подключаются адаптерами | Ни один внешний отчёт не даёт все каскады, разрешающие сигналы и сбросы [ST 4, ST 5.2] |
| Р3 | **Свойства – отдельные проверочные модули на Verilog**, читаются `read_verilog -formal` и подключаются к сетям нетлиста. RTL пользователя не меняется | yosys-slang не принимает `assert property`, `$past`, `(* gclk *)` и теряет метки [MC 2.1, MS 3.0]; родной фронтенд Yosys их принимает и сохраняет имена свойств |
| Р4 | **Модель «разрешающих сигналов» Kebaili** (`en_s`, `en_cdc`, `en_d`) – общая основа для мультиплексора с разрешением, рукопожатия и FIFO | Четыре маленьких свойства заменяют протокольные; у Kebaili время упало с 44 ч до 40 мин [TH 6] |
| Р5 | **Своя модель времени с двумя реализациями:** «тики» (основная) и `clk2fflogic` (эталонная) | Тики вдвое уменьшают глубину [MC 2.3]; эталон нужен, пока совпадение вердиктов не доказано примерами |
| Р6 | **Локализация циклом CEGAR**, а не одной вырезкой: уточнять только те точки разреза, от которых зависит контрпример | Plassan: 125 из 125 свойств на SoC при фокусе до 200 регистров [TH 2.1] |
| Р7 | **Строгая политика итогов:** «доказано» только при разделённых тактах, неограниченном доказательстве, достигнутом покрытии и проверенных допущениях | Иначе ложные успехи, как у `cdc_primitives` без `multiclock` [OSS 4.11] |
| Р8 | **Допущения – объекты первого класса:** у каждого есть проверочный двойник, у каждой проверки – список `depends_on` | Структурные средства принимают ограничения на веру [ST 5.4] |
| Р9 | **Метастабильность – вставкой модели в нетлист** (проход Yosys по приёмным триггерам), по умолчанию только в конусе одного свойства | Как `check_cdc -metastability -inject`; цена растёт с числом моделей [MS 4.2, MS 4.3] |
| Р10 | **Запуск – свой планировщик** заданий SBY с портфелем движков, кешем по хешу конуса и выполнением на ПК | Сотни задач, 28–32 потока, повторные прогоны после правок [MC 6] |

## 4. Компоненты

### 4.1. Фронтенд [1]
- Один сценарий Yosys на проект:
  - `read_slang -f <файл> --top <верх>` плюс ключи пользователя (`--relax-enum-conversions` и т.п.);
  - `hierarchy`, `proc`, `flatten`, `memory_collect`, `opt_clean`;
  - `setundef -anyseq t:$buf` (ловушка Yosys 0.71) [локальные заметки];
  - выгрузка `design.il` (для заданий SBY) и `netlist.json` (для анализа на Python).
- **Ячейки синхронизации пользователя** (`sync_cell` и т.п.) по желанию не раскрываются при `flatten`: так их проще распознать и доказать один раз отдельно [ST 5.2].
- Имена: у каждой сети сохраняются иерархическое имя после `flatten` и атрибут `src` (файл и строка) для отчётов.
- Кеш по хешу исходников, сценария и версий инструментов.

### 4.2. Среда [2]
Один внутренний объект «среда», три источника:
1. **Свой YAML** – основной. Имена параметров по возможности из стандарта Accellera 1.0 [FP 5.1]:
   - такты: `period`, отношение (`free` | `ratio: [min, max]` | `fixed: m:n`), группы (`asynchronous`, `exclusive`);
   - сбросы: полярность, асинхронный или синхронный, порядок снятия (`reset_assertion_sequence`);
   - асинхронные входы и их виртуальные домены (`async_a`, `async_b`);
   - сигналы: `constant`, `static`, `quasi_static` (меняется только в режиме настройки), `exclusive`, `hamming1` (код Грея), `clock_select` (ожидание подтверждения переключения через `on`);
   - протоколы входов (APB: регистр не пишется во время передачи и т.п.);
   - пользовательские ячейки: имя модуля, тип схемы, порты req, ack, data;
   - исключения переходов с обоснованием.
2. **Подмножество SDC:** `create_clock`, `create_generated_clock`, `set_clock_groups`, `set_case_analysis`, `set_false_path`. Разбор без исполнения Tcl.
3. **Подмножество Accellera Tcl** – как допущения на границе блока [ST 3.3]. Тоже без исполнения.

Каждое допущение получает идентификатор, источник (`yaml`, `sdc`, `accellera`, `inferred`) и флаг `verify`: проверять ли его двойником-утверждением.

### 4.3. Структурный анализ [3] и адаптеры [3a]
Обобщение `локальный структурный анализатор` [ST 5.2], на Python по `netlist.json`.

1. **Домены:**
   - обратный проход от тактового вывода триггера;
   - объединение производных тактов (union-find), генерируемые такты из SDC;
   - `set_case_analysis` для мультиплексоров тактов;
   - список триггеров, домен которых не определён, – в отчёт, а не молча.
2. **Сбросы:** роль сброса – только по выводу ячейки; полярность и корень отслеживаются через буферы, инверторы и триггеры. Однотактные пары с разными reset-корнями образуют отдельный `reset_crossings`, а не обычный CDC. Сброс, сформированный в другом тактовом домене, записывается в `reset_signals`; `reset_release` требует снятия только на фронте приёмника. Несовпадение декларации `reset_polarity` и reset-значения producer фиксируется в `reset_polarities`; первое получает структурный `unsafe`, второе проверяется `reset_value`. Синхронный reset из другого домена распознаётся по `$mux` на D с константной ветвью и проверяется `srst_release`. Комбинационная логика на reset-пинах записывается в `reset_logic` и получает структурный `unsafe`; два и более независимых входа классифицируются как RDC-005, а FF-источники как RDC-004; `$mux` непосредственно на reset-пине образует RDC-006. Голова reset-цепочки с D, привязанным к asserted-значению, записывается в `reset_stuck` и получает структурный `unsafe`. `reset_chains` фиксирует authored-синхронизаторы, а `reset_domain_misses` сравнивает их домены с потребителями сырого порта. `note` и `warning` не считаются нарушением; early tap, чужой домен, комбинационный выход и foreign drive получают `unsafe`. `reset_dual_uses` отделяет async reset-пин от sync reset-ветви D.
3. **Переходы:** на уровне бит, затем группировка в векторы и группы сходимости (как пары бит и пары векторов у Jasper и `локальный структурный анализатор`).
4. **Схемы:** `ndff`, `ndff_bus`, `gray_bus`, `mux_enable`, `handshake`, `pulse_toggle`, `async_fifo`, `reset_sync`, `reset_domain`, `clock_mux`, `static`, `user_cell`, `external_sync`, `none`. Для каждой – все каскады, а не только первый и последний.
5. **Разрешающие сигналы** по Kebaili [TH 6] и универсальный квалификатор по Kalel [FP 5.1]: тройка `en_s`, `en_cdc`, `en_d`, для FIFO – по адресам. В отчёт – **все** кандидаты, а не первый.
6. **Кандидаты на проверку:** сходимость, «иголки» перед синхронизатором, логика в цепочке синхронизатора не отбрасываются как шум, а сразу становятся кандидатами для формальной части [ST 5.2].
7. **Ранний поиск сигналов настройки** в конусах тактов и разрешений: предлагаются как `static` или `quasi_static` [TH, вывод 6].

**Адаптеры** переводят внешние отчёты в ту же модель и сопоставляют имена с нашим нетлистом. Недостающие поля (каскады, разрешающие сигналы) досчитывает наш анализ. Порядок адаптеров:
1. `локальный структурный анализатор` (CSV) – для сравнения на референсном блоке;
2. rtl-buddy-cdc;
3. icarium и clockguard;
4. OpenCDC.

Отчёты Jasper используются только для сопоставления находок, не как вход для доказательства.

### 4.5. Шаблоны свойств

Общие правила шаблонов:
- **стиль (E2a):** состояние – в триггерах по фронту такта, утверждения и покрытия – только в `always @(*)`; тактированные утверждения ломают модель тиков;
- шины и FIFO – одно свойство со случайно выбранным номером бита или слова (`$anyconst`), а не свойство на бит [MC 3.6];
- неограниченные формы (`##[1:$]`, «когда-нибудь») – ограниченные с параметром `max_latency` в тактах приёмника [FP 5.2];
- точные задержки в свойствах расширяются на такт за каждый каскад с моделью MSI [MS 4.4].

### 4.6. Модель времени
Одна абстракция «глобальный шаг», две реализации:

1. **Тики (основная).** Один глобальный такт. Триггеры домена `d` обновляются, когда `tick_d = 1`. На каждом шаге срабатывает непустое подмножество доменов. Реализация (проверено, E2): в обёртке такт домена – ICG с защёлкой (`always @* if (!gclk) en_d = tick_d; clk_d = gclk & en_d`), затем `opt_clean` и `formalff -declockgate`. SBY запускается без `multiclock`.
2. **`clk2fflogic` (эталонная).** `multiclock on`, такты – свободные входы, ограничения в обёртке на `$global_clock`. Обёртка читается `read_verilog -formal`, не через slang (ошибка #405).

Режимы отношения тактов (из среды): `free` (по умолчанию, справедливость не нужна для safety-свойств), `ratio: [Nmin, Nmax]` по Kapschitz и Ginosar, `fixed: m:n`, `skew` – однотактная модель с перекосом сигналов на ±1 такт для дешёвой проверки сходимости [OSS 4.1]. Отношение можно задать диапазоном через `$anyconst`: один прогон покрывает несколько соотношений.

Правила:
- входы домена меняются только на его тике;
- однодоменные проверки идут в однотактной модели без лишних тактов;
- **запрет:** если в конусе два домена и больше, а модель однотактная не по построению (тики), задание не собирается;
- на отладке все шаблоны гоняются в обеих реализациях, вердикты должны совпасть (E1).

**Условия сохранения safety (рабочая формулировка, пока не машинная теорема).** Пусть свойство зависит только от значений на фронтах доменов и от истории между ними, входы меняются только на своих фронтах, на каждом глобальном шаге активно непустое подмножество доменов, а асинхронные сбросы разрешены в любом шаге. Тогда каждое чередование фронтов реальных часов можно представить как последовательность тиков, и каждая последовательность тиков допускает такое же чередование реальных фронтов (совпадающие фронты группируются в один шаг). Поэтому наборы трасс для safety должны совпадать. Если свойство использует внутришаговый порядок нулевой задержки, оно выходит за эти условия; capture-period M4 вместо этого явно строит overapproximation по фронтам приёмника.

Практическое подтверждение на текущем наборе: все сквозные примеры и `experiments/e_m4_async` дают одинаковые вердикты в обеих моделях, CRT formal имеет 209/213 совпадений. Обязательны `cover` предпосылки и skew-инъекции, чтобы совпадение не было вакуумным. Это дифференциальное свидетельство, а не доказательство для произвольного дизайна.

### 4.7. Модель метастабильности
- **Основная модель M2a** `ofcdc_msi_d` на сети D приёмного триггера: каждый бит независимо берёт текущее значение или значение до последнего изменения [MS M2]. Модуль читается `read_verilog -formal`.
- **Вставка (проверено, E-MSI):** разрез сети D приёмного триггера командами Yosys (раздел 4.8, п. 5), модель стоит в обёртке. Окно зависит от модели времени: для тиков – только изменение в текущем шаге, для `clk2fflogic` – два шага. Для ячеек-синхронизаторов из библиотеки возможна и замена модуля при чтении.
- **Включение:** по умолчанию на приёмниках одного перехода (шаблоны) или в конусе одного свойства (функциональные свойства блока). Глобально – только опцией для отладки.
- На каждый экземпляр – `cover` факта инъекции; для групп сходимости – покрытие сочетаний «бит запоздал».
- **M5** `ofcdc_msi_propagate` вставляется на D второго каскада после M2a первого. Инъекция первого создаёт независимый `pending` для каждого бита; на первом сенсибилизированном изменении D второй каскад выбирает старое или новое значение только для соответствующих битов, после чего их события сбрасываются. История отсчитывается по фронтам приёмника: для ticks используется текущее изменение, для `clk2fflogic` – изменение на предыдущем фронте и более старое значение. Покрытия первой, второй и отложенной инъекции обязательны. Шаблон `rise_latency` калибрует функциональный эффект на монотонном управляющем сигнале. Шаблон `settled` проверяет более общее свойство D → Q второго каскада и потому подходит для логики между каскадами. Отложенный `cap` выбирает состояние после фронта, а отдельные регистры `check_*` фиксируют его для утверждения; это не создаёт производных тактов и работает одинаково в ticks и `clk2fflogic`. `options.m5_checks` предлагает такую проверку только при известных именах D обоих каскадов, совпадающем сбросе и постоянном enable, включая распознавание recirculating mux. Допускаются непрерывные срезы векторов и сгенерированные имена нетлиста, поскольку frontend анализа и формальных задач совпадает. Список `m5_targets` содержит все пары «первый каскад → приёмник», включая fanout и один комбинационный элемент на ветви. Для ячеек из раздела `cells` T-CELL передаёт M5-опции во внутренний прогон, а `results.json` сохраняет полную секцию `cells.<модуль>` с исходами и покрытиями. `m5_group` объединяет независимые проверки в одно SBY-задание на такт, дедуплицирует первую M2a, но сохраняет отдельные M5, утверждения и покрытия. Это не семантическое объединение свойств; в замере режим замедляет решение и потому выключен по умолчанию. Для портфеля движков `m5_prove_engine`, `m5_cover_engine` и `m5_cover_depth` переопределяют общие параметры только в заданиях с M5. В том же grouped-примере rIC3 сократил время с 45,10 до 27,40 с, но глобальные умолчания не меняются. Для атрибута `cdc_sync` дополнительно распознаются N упакованных стадий одной векторной ячейки при условии `D[kW+i] == Q[(k-1)W+i]`; на первые две ставятся M2a/M5, а остаток D сохраняется через `remaining_d`. Другие формы атрибутированных цепочек этот путь не раскрывает. Для NDFF проверка основной цепочки связывается с переходом; дополнительные fanout-проверки остаются самостоятельными, поэтому формальное доказательство не снимает `no_scheme` или другое структурное предупреждение. На точке сходимости `m5_conv_<точка>` склеивает исходные и синхронизированные сигналы в векторы и применяет `nonew` только при совпадении полной ширины каждого источника с шириной его приёмника: новая комбинация допустима только если источник уже держал её. Это функциональная проверка независимых задержек, а не подсчёт изменений `onechange`. Ограничение частот входит в модель среды: Gray не исключает переупорядочивание двух переходов при произвольно быстром источнике.
- **M6** `ofcdc_msi_reset` вставляется на reset-вывод приёмного триггера. На снятии сброса `$anyseq` независимо выбирает для каждого экземпляра, останется ли он в сбросе ещё на один фронт. Шаблон `reset_latency` проверяет границу полной задержки; отдельные покрытия требуют обоих исходов, с задержкой и без неё.
- **M7** `ofcdc_skew_cap` вставляется на D первого каскада и выбирает для каждого бита значение на предыдущем или текущем фронте приёмника. Шаблон `async_nonew` проверяет отсутствие значений, которых источник никогда не держал. В отличие от M2a окно привязано к периоду приёмника, а не к последнему изменению; в отличие от M4 копируется не комбинационный конус, а сам асинхронный вход. Поэтому при нескольких изменениях источника за период приёмника даже код Грея может дать настоящий контрпример; допустимое соотношение частот должно быть частью среды проверки.
- Структурные шаблоны (T-GRAY, T-EN, T-GLITCH, T-CONV без MSI) доказываются **без** модели. Функциональные свойства блока – в два прогона: без модели и с ней; `options.msi_ablate` создаёт независимый контроль `*_noms`, а новое падение помечается `sensitive`. Вердикт перехода определяется только основным прогоном с MSI.
- Поиск виновного экземпляра – повторным прогоном с выключением моделей группами (метод истёкшего патента Mentor). Автоматический поиск через мягкие ограничения не делаем: патент Cadence US11892504 действует до 2042 года [MS 4.4].
- Порядок моделей: M2a → M6 (снятие сброса, для CASE-8) → M7 (разброс асинхронных входов, для CASE-4) → M4 (смешивание на входах конуса, для CASE-7) → M5 (распространение в своём домене).

### 4.8. Сборка задач [5]
Для каждой проверки или группы:
1. **Опора** – сети, на которых стоит свойство и его допущения.
2. **Начальный фокус** – опора плюс L уровней триггеров (L = 1–2); для T-EN и T-FIFO – сигналы мета-модели и их ближайшая логика, данные и выходы синхронизаторов отрезаются [TH, вывод 3].
3. **Разрезы** вне фокуса – `abstract -state` в своём домене: свободное значение меняется только на тике своего домена. `cutpoint` под несколькими тактами не применяется: он даёт «иголки» между фронтами и ложные контрпримеры [MC 5].
4. **Нельзя резать** такты и сбросы.
5. **Подключение проверочного модуля** (проверено, E5): `cd <верх>; rename -output <сеть> ofcdc_sN; cd ..`, затем обёртка на Verilog с экземплярами проекта и проверочного модуля. Разрез сети для модели метастабильности: `rename -wire -suffix` (имя ячейке приёмника), `add -output`, `add -input`, `connect -set`, `connect -port <ячейка> D` (E-MSI).
6. **Группы:** свойства с близкими опорами (порог близости 0,9, не больше 50 в группе) [MC 3.1].
7. Итог сборки – папка задания: `design_<hash>.il`, проверочные модули, `.sby`, `task.json` с описанием (что проверяется, какие разрезы, какие допущения).

### 4.9. Исполнитель [6]
Этапы на группу [MC 6.3], лимиты уточняются на референсном блоке:

| Этап | Что делается | Лимит |
|---|---|---|
| 0 | однодоменные – в однотактной модели; «нет схемы» – сразу итог | – |
| 1 | быстрый поиск контрпримеров: `smtbmc` или `abc bmc3`, 20–30 шагов | 60 с на группу |
| 2 | контрпример абстракции → разбор, от каких разрезов он зависит, уточнение фокуса (CEGAR, до 3–5 раундов) | 60 с на раунд |
| 3 | доказательство: `abc pdr` на группе, параллельно rIC3 по одному на нерешённые | 120–300 с на свойство |
| 4 | приём «остальные свойства – допущения» с задержкой на шаг (`chformal -delay 1`); инварианты доказанных – в допущения | 300–600 с |
| 5 | последние трудные: портфель rIC3, k-индукция с простым путём | 600–1800 с |

Покрытия идут отдельной задачей `cover` в той же модели времени. `cover: FAIL` и `TIMEOUT` от SMTBMC означают только то, что трассу не нашли в пределах заданной глубины или времени; оба исхода дают `unknown`. Для `vacuous` требуется отдельное неограниченное доказательство недостижимости покрытия.

**Разбор контрпримера для CEGAR** [TH 2.1]: команда `cegar` уже поддерживает явные `cut`/`cut_mode` и жадное уточнение: разрез убирается, если контрпример сохраняется без него. Окончательный статус всегда получается на полной модели; абстрактный контрпример получает `confirmed` или `discharged`, а абстрактные покрытия не считаются достигнутыми на исходной схеме. Нетлист переиспользуется между раундами после проверки точного совпадения `frontend.ys`. Для `en_stable` начальный фокус строится автоматически по границе конуса enable, для `gray` – по next-state логике измеряемой шины. По VCD контрпримера разрезы дополнительно упорядочиваются по активности около шага нарушения; это только приоритет, а не обоснование. `cut_evidence` отделяет сохранение контрпримера без разреза (`not_required`) от доказанного исчезновения (`discharges`) и незавершённого раунда (`inconclusive`); статусы proof сохраняются отдельно от cover. Следующий шаг – обоснование по конкретной трассе и нетлисту и расширение автоматического фокуса на остальные шаблоны.

**Выполнение:**
- локально (для маленьких примеров) или на ПК по ssh (rsync папок заданий, `setsid`, гашение по группе процессов);
- по одному процессу SBY на поток, общий бюджет времени, «сначала лёгкие»;
- многопоточный портфель rIC3 – не больше одного одновременно;
- на ПК 16 потоков (Ryzen 7 5700X), а не 28–32: оценки времени в [MC 6.4] пересчитать.

**Кеш:** ключ – хеш RTLIL конуса, текста свойства, допущений, модели времени, версий инструментов, движка и ключей. Значение – итог, глубина, трасса, инвариант PDR, время. После правки RTL перепроверяются только проверки с изменённым конусом.

### 4.10. Итоги и вердикты [7, 8]
**Статусы проверки:**

| Статус | Условие |
|---|---|
| `proven` | неограниченное доказательство, такты разделены, все покрытия достигнуты |
| `proven_assuming` | то же, но опирается на допущения в состоянии `accepted` (не доказанные) или на другие свойства группы |
| `bounded(N)` | нет контрпримера до глубины N; в исключения не идёт без явного разрешения |
| `cex` | контрпример подтверждён на полном конусе |
| `cex_env` | контрпример, в котором участвуют свободные входы без протокола в среде |
| `cex_abstract` | контрпример только на абстракции, уточнение не закончено |
| `vacuous` | предпосылка или переключение сигнала свойства недостижимы |
| `unknown` | лимит исчерпан; в отчёте – размер фокуса, число раундов, обоснованные разрезы |
| `not_run`, `error` | не запускалось; ошибка сборки или движка |

**Вердикт по переходу** – функция от статусов его проверок и структурного итога:
- `safe` (все проверки `proven`), `safe_assuming`, `unsafe` (есть `cex`), `env_dependent` (только `cex_env`), `no_scheme`, `unresolved`, `waived`;
- **отзыв:** если допущение опровергнуто (`refuted`), все вердикты, у которых оно в `depends_on`, становятся `unresolved` с указанием причины;
- **снято доказательством:** структурные находки (сходимость, «иголки», логика в цепочке синхронизатора) с доказанным T-CONV или T-GLITCH получают итог «снято доказательством», как условные исключения Jasper.

### 4.11. Вывод допущений [9] (после MVP)
Алгоритм Plassan, гл. 5 [TH 3]:
- набрать 5–10 разных контрпримеров одного свойства;
- искать кандидатов по шаблонам в пределах одного домена;
- 8 фильтров строго по порядку: входное условие → единственность → общая причина → импликация → тривиальность → совместность → вакуумность → проверка утверждением;
- показать короткий список с ранжированием и столбцом «следует из».

Пользователь отвечает «да/нет». Принятые попадают в YAML с `source: inferred` и действуют для всех свойств. Простой вариант до полного алгоритма – предлагать на каждый обоснованный разрез допущения `constant 0/1`, `static`, `quasi_static`.

## 6. Политика корректности

1. Каждый шаблон проверяется в обе стороны: верная схема – `proven`, испорченная – `cex`.
2. **Мутационные проверки шаблонов:** для каждого примера автоматически создаются испорченные варианты (убран каскад, двоичный код вместо Грея, данные меняются до подтверждения, раздельные сбросы). Каждая мутация должна быть поймана.
3. **Дифференциальная проверка моделей времени:** тики и `clk2fflogic` дают одинаковые вердикты на всём наборе примеров.
4. Неправильная модель метастабильности должна давать заметный провал на контрольном примере [MS 3.9].
5. Нет `proven` без достигнутых покрытий и без разделения тактов.
6. Версии инструментов – в ключе кеша и в отчёте.

## 7. Внешние ограничения и риски

| Риск | Мера |
|---|---|
| Модель тиков может терять поведение при асинхронных сбросах (E4 не проверен) | дифференциальная проверка с `clk2fflogic` на каждом примере; E4 на этапе 1 |
| ABC PDR в Yosys 0.71 медленнее, чем в 0.59 | rIC3 в портфеле; сравнение E7, E8 |
| Эвристики выбора разрезов Plassan закрыты (Synopsys Confidential) | свои эвристики, проверка на FIFO Plassan и референсный блок |
| Патент Cadence на поиск виновного перехода | не повторять; только ручное выключение моделей |
| Лицензии примеров | внешние наборы не копировать, а загружать фиксированным коммитом; код без лицензии (async-fifo-cdc, cdc_primitives) и GPL (ZipCPU `afifo.v`) не брать |
| Стандарт Accellera под «All rights reserved» | текст не класть в репозиторий; реализовать только формат, права уточнить |
